# BRIEF — Интерактивная презентация «Вайбкодинг для самых маленьких»

Единый контракт для всех подагентов. Главный агент интегрирует наработки в `index.html`.

## Что строим
Одностраничная HTML-презентация (deck) уровня Apple Keynote по статье Habr
https://habr.com/ru/articles/1107966/ («Вайбкодинг для самых маленьких. Часть 1»).
Русский язык, 10 слайдов, ощущение нативного приложения: 60 FPS, пружинные
анимации, морфинг общих элементов, Bento-карточки с матовым стеклом, живой
интерактив внутри слайдов.

## Жёсткие технические правила
- Без сборщиков и зависимостей. Vanilla HTML/CSS/JS. Классические `<script>`
  (НЕ ES-модули) — итоговый файл открывается напрямую по file://.
- Анимировать только `transform` и `opacity` (+ умеренно `filter: blur`).
  Никаких анимаций свойств, вызывающих layout.
- Иконки — только inline SVG, monoline stroke 1.6–1.8px, `currentColor`.
  Emoji в роли иконок запрещены.
- Ноль внешних ресурсов. Шрифты — системный стек:
  `-apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text", "Inter", "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`
  (на macOS даёт SF Pro, на других — Inter/Segoe). Без CDN, картинок, Google Fonts.
- `prefers-reduced-motion: reduce` — переходы и анимации отключаются,
  View Transitions API не используется.
- Доступность: `:focus-visible` на всех интерактивных элементах, aria-метки,
  контраст, клавиатурная навигация.
- Адаптив: 1440×900 (desktop) → 390×844 (мобильный) без горизонтального скролла.
- Тёмная тема по умолчанию: `<html lang="ru" data-theme="dark" data-zcode-design>`,
  переключатель светлой. Все цвета через CSS-переменные на `:root` и
  `[data-theme="light"]`.
- Запрещён «AI-шум»: бесконечные пульсации, токсичные неоновые тени, дефолтные
  indigo/violet градиенты, мельтешение. Одно смелое решение, остальное — тишина.

## DOM-контракт (обязателен для всех)
```html
<html lang="ru" data-theme="dark" data-zcode-design>
<body>
  <main id="deck">
    <section class="slide" data-slide="0" data-notes="заметки спикера одним абзацем">
      <div class="slide-inner"> … контент слайда … </div>
    </section>
    <!-- 10 секций. Активная: .slide.is-active; уходящая на время перехода: .slide.is-exiting -->
  </main>
  <!-- Хром интерфейса (создаёт deck.js или index.html — см. DESIGN.md): -->
  <div class="progress"><div class="progress-bar"></div></div>
  <div class="slide-counter">3 / 10</div>
  <button class="theme-toggle" aria-label="Переключить тему">…</button>
  <section class="overview" id="overview" hidden> … сетка миниатюр слайдов … </section>
  <aside class="presenter" id="presenter" hidden> … заметки + таймер … </aside>
  <div class="laser" id="laser" hidden></div>
  <!-- Точки монтирования виджетов внутри соответствующих слайдов: -->
  <div data-widget="sandbox"></div>
  <div data-widget="tools"></div>
  <div data-widget="pulse"></div>
</body>
```

## JS-контракт
- `js/deck.js` — классический скрипт (IIFE), создаёт `window.VibeDeck`:
  - `next()`, `prev()`, `goTo(i)`, `toggleOverview()`, `state = {index, total}`
  - события на `document`:
    `deck:change` → detail `{index, total, dir}` (dir: 1/-1),
    `deck:overview-toggle` → detail `{open}`,
    `deck:ready`
- `js/widgets.js` — классический скрипт (IIFE), грузится ПОСЛЕ deck.js:
  - находит `[data-widget="sandbox|tools|pulse"]` и инициализирует их;
  - слушает `deck:change` (сброс/перезапуск анимаций при входе слайда);
  - экспортирует `window.VibeWidgets = { initAll }`.
- Клавиатура: `←` `→` `Space` — навигация; `G` — обзор-сетка; `S` — панель
  спикера; `L` (удержание) — лазерная указка; `T` — тема; `Esc` — закрыть
  обзор/панель. Не перехватывать клавиатуру, когда фокус в `input`,
  `textarea`, `[contenteditable]`. Space — `preventDefault` только когда
  перехватили.
- Колесо/трекпад: порог накопления + блокировка ~900 мс после срабатывания.
- Тач: свайп при |dx| > 48px и |dx| > |dy|*1.2.
- Смена слайдов: View Transitions API (`document.startViewTransition`) c
  `view-transition-name` на общих элементах (`data-vt="имя"`), плавный
  fallback на CSS-классы, если API недоступен.
- Hash-адресация: `#/4` — при загрузке восстанавливать слайд, при смене —
  обновлять (replaceState, без скролла).

## Структура презентации: 10 слайдов
1. **hero** — титул «Вайбкодинг для самых маленьких», подзаголовок, источник (статья Habr).
2. **statement** — «Программирование на естественном языке» + два определения (Collins Dictionary и Карпати).
3. **bento** — «Кому это нужно»: агенты уже работают с 1С, Notion, Slack, GitHub, Stripe, amoCRM… Агентная грамотность нужна всем, порог входа упал.
4. **diagram** — «Как устроен агент»: LLM → Tools → MCP, цикл ReAct (Reason → Act → Observe), Harness — среда выполнения.
5. **widget:tools** — «Инструменты»: Codex, Claude Code, Cursor, OpenCode, Hermes Agent.
6. **widget:sandbox** — «Как ставить задачу»: «Сделай красиво» vs промпт с контекстом (функциональность / дизайн / ограничения).
7. **timeline** — «3 запроса → готовое приложение»: кейс Poster Studio (создай → улучшим → проверь).
8. **reference** — «Настраиваем ZCode (GLM)» — та же схема настройки, что у Codex в статье, но для этой среды: модели GLM-5.3 (мощная — сложные задачи, аналог Sol/Astra) / GLM-5.3-Flash (повседневные задачи, аналог Terra) / glm-5.3-flashx (самая экономная, аналог Luna); уровни рассуждений low / high / max (по логике статьи: выше уровень — глубже анализ, но дороже и дольше; простые задачи решаются и на низком); режимы доверия: plan (агент только планирует) → build (пауза перед правками) → yolo (полная автономия — в статье совет: не давай полный доступ сразу); скиллы и MCP-интеграции как в статье (MCP от Anthropic).
9. **widget:pulse** — «Пульс аудитории»: опрос про опыт вайбкодинга + мини-квиз.
10. **finale** — «Код пишет агент. Смысл пишешь ты.» + анонс части 2 + кнопки реакций.

## Данные для виджетов (фиксированные, источник — статья)

### sandbox — симулятор «Промпт → Результат»
Режим A «Сделай красиво»:
- промпт: «Сделай мне красивый сайт, чтобы всё летало»
- превью: «кривой» макет (разнобой размеров, съехавшие блоки, случайные цвета)
- метрики: соответствие замыслу 25%, итераций до результата 10+, доводка вручную — высокая
- код: нагромождение inline-стилей, всё в одном файле без структуры
Режим B «Промпт с контекстом» (структура из статьи):
- Функциональность: редактор постеров — заголовок, подзаголовок, дата, место; живое превью; экспорт PNG 1080×1350
- Дизайн: минимализм, панель слева, превью справа, тёмная тема + один акцент
- Ограничения: один index.html, HTML/CSS/JS без библиотек, Canvas API, запуск по file://
- метрики: соответствие 90%, итераций 3, доводка минимальная
- превью: аккуратный макет постера

### tools — Bento-матрица инструментов
| Инструмент | Вендор | Тезис | Деталь | Сценарий | Скорость | Контроль |
|---|---|---|---|---|---|---|
| Codex | OpenAI | Агентная среда от создателей ChatGPT | Приложение, IDE-расширение и CLI. Сам пишет код, ставит библиотеки, запускает и чинит приложение | Просто начать | 4/5 | 3/5 |
| Claude Code | Anthropic | Прямой конкурент Codex | Терминал, приложение, IDE и браузер. Глубокая интеграция с моделями Claude | Просто начать | 4/5 | 3/5 |
| Cursor | — | Редактор кода со встроенным агентом | Максимум ручного контроля: видишь структуру проекта и правишь код параллельно с агентом. Модели OpenAI, Anthropic, Google | Работа в редакторе | 3/5 | 5/5 |
| OpenCode | — | Open-source агент | Свобода выбора: любой провайдер моделей, своя оплата, даже локальные модели | Свобода моделей | 3/5 | 4/5 |

Фильтры-сценарии (чипы): «Просто начать», «Работа в редакторе», «Свобода моделей», «Не только код».
Ползунок «Скорость ↔ Контроль» подсвечивает подходящий инструмент.

### pulse — живой опрос (2 вопроса, переключатель)
Q1 «Какой у тебя опыт вайбкодинга?»: «Только слышал» / «Пробовал в чате» / «Поручаю задачи агенту» / «Живу в агенте»
Q2 «Что делает команда /compact?»: «Сжимает историю диалога в контексте» (верно) / «Сжимает файлы проекта» / «Включает компактный интерфейс» / «Ускоряет модель»
Голос → анимированные SVG/CSS-бары с пружинным переходом, счётчик, сохранение
в localStorage, предзаполненные демо-голоса, чтобы график не был пустым.

## Общий словарь имён (обязателен для Подагентов 2 и 3)
CSS-переменные — эти ИМЕНА фиксированы, значения задаёт Подагент 2 в
`tokens.css`; Подагент 3 потребляет их с fallback:
`--bg`, `--bg-elev`, `--text`, `--text-2`, `--text-3`,
`--accent`, `--on-accent`, `--card-bg`, `--card-border`, `--card-hover`,
`--success`, `--danger`,
`--radius-card` (24–28px), `--radius-md` (18–20px), `--radius-sm` (10–12px),
`--ease-out` (cubic-bezier(0.32,0.72,0,1)), `--ease-spring` (cubic-bezier(0.34,1.56,0.64,1)),
`--dur-1` (~160ms), `--dur-2` (~320ms), `--dur-3` (~560ms),
`--font-body` (системный стек), `--font-mono` (ui-monospace, SF Mono, Menlo…).

Классы раскладок слайдов (на `<section class="slide layout-hero">` и т.д.):
`layout-hero`, `layout-statement`, `layout-bento`, `layout-diagram`,
`layout-timeline`, `layout-reference`, `layout-widget` (слайд-виджет),
`layout-finale`.
Data-атрибуты: `data-widget`, `data-vt` (view-transition имя), `data-reveal`
(появление при входе, порядок через `--i`), `data-notes` (заметки спикера),
`data-kicker` + `data-title` (короткие тексты для мини-карточек обзора G).
Стили виджетов — только с префиксом `.w-` в `widgets.css`.

## Дизайн-язык (точные значения фиксирует Подагент 2 в tokens.css / DESIGN.md)
- Эстетика Apple Keynote: глубокая тёмная тема, воздух, крупная типографика
  через `clamp()` с tight tracking (−0.02…−0.04em) для заголовков.
- Bento-карточки: полупрозрачный фон, граница 1px rgba(...),
  border-radius 20–28px, `backdrop-filter: blur(24px) saturate(1.6)`.
- Один акцент; НЕ Tailwind-indigo и НЕ фиолетовый. Ориентир — системная
  палитра Apple (#0A84FF синий / #30D158 зелёный / #FF9F0A оранжевый),
  финальный выбор за арт-директором.
- Движение: переходы `cubic-bezier(0.32, 0.72, 0, 1)`; лёгкая пружина
  `cubic-bezier(0.34, 1.56, 0.64, 1)` для pop-in; тактильность
  `:active { transform: scale(0.97) }`; staggered reveal при входе слайда
  (шаг 40–70ms через `transition-delay: calc(var(--i) * 60ms)`).
- Переход слайдов: уходящий scale 1→1.04 + fade + blur, входящий
  0.96→1 + fade (+ вертикальный параллакс 24px). Морфинг общих элементов
  через View Transitions (`data-vt`).
- Печать: `@media print` — все слайды друг под другом, альбомная ориентация.
